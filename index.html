Second-monitor setup — Ubuntu & Fedora

Choose your distribution to see commands for its GNOME desktop. Run commands in a terminal on your Linux computer. This website cannot run them for you.

Important: This software method uses GNOME Remote Desktop and an Android RDP client. It is not connected to this website’s host-code viewer. The extended screen is created/used when a compatible RDP client connects—not just by running the setting command.

This guide is not for Kubuntu, Xubuntu, Fedora KDE, Sway, Server installs, or Fedora Atomic/Silverblue. Desktop/version support varies. It does not install a new desktop.

1. Check your system

cat /etc/os-release
printf '\nDesktop: %s\nSession: %s\n' "$XDG_CURRENT_DESKTOP" "$XDG_SESSION_TYPE"
gnome-shell --version

Confirm the distribution matches your selection and that your current desktop is GNOME. This guide targets GNOME on Wayland. If it says x11, stop and check whether your installed system offers a GNOME Wayland session at login; do not disable or replace your current desktop based on this guide.

2. Install GNOME Remote Desktop if missing

It may already be installed. These commands contact your distribution’s repositories and may install packages with administrator approval. Review the package manager’s prompt; no automatic yes flag is used.

3. Check extension support
gsettings range org.gnome.desktop.remote-desktop.rdp screen-share-mode
Continue only if the output lists 'extend'. If it reports “No such schema/key” or does not list extend, stop. Installing the package alone does not guarantee support in your GNOME version.
4. Record the current setting
gsettings get org.gnome.desktop.remote-desktop.rdp screen-share-mode
Save the printed value if you want to restore it later.
5. Enable extended-display mode
Run this as your normal desktop user, without sudo. It changes the RDP sharing mode for your account:
gsettings set org.gnome.desktop.remote-desktop.rdp screen-share-mode 'extend'
6. Enable sharing and connect Android
  1. Open Settings → System → Remote Desktop → Desktop Sharing. On some versions it is under Settings → Sharing.
  2. Enable Desktop Sharing for your current session, not Remote Login, which can open a separate login session. Set strong RDP credentials and note the address and port shown in Settings.
  3. Keep Linux signed in. Put Android and Linux on the same trusted local network.
  4. Open an Android RDP client. Add the Linux address and the port shown in Settings, then sign in using the RDP credentials you configured. Verify the target before entering credentials.
  5. Once connected, open Linux display settings, arrange the extended screen next to the main display, and drag a window onto it. If it only mirrors or does not create an output, your GNOME/client combination needs version-specific troubleshooting; this page cannot force support.
Use Remote Control only if you want the RDP client to control the computer. Do not post credentials, forward the RDP port to the internet, or disable your firewall.
Connection blocked?
Check Desktop Sharing is enabled, you used its actual port, Linux is signed in, and the network does not isolate devices. A firewall rule may be required. Use your distribution’s instructions to allow only your trusted local network and the displayed port. This guide deliberately does not open RDP broadly or modify firewall rules automatically.
7. Stop and undo
Disconnect the RDP client and turn off Desktop Sharing when no longer needed. To restore your previous sharing mode, use gsettings set with the exact value you recorded. Alternatively, this resets to the installed schema’s default, which may differ from your old value:
gsettings reset org.gnome.desktop.remote-desktop.rdp screen-share-mode
Prefer to view the second display in this website?
This page has no RDP client or RDP-to-browser gateway. The GNOME commands above do not add one. To use the existing host-code viewer, first prepare an extra display that your browser can capture—for example using a compatible HDMI/DisplayPort dummy plug—and configure an extended rather than mirrored layout in Linux display settings.
  1. Open this hosted website on Linux and Android. Linux capture requires a supported desktop browser on HTTPS or localhost. Android must use a reachable website address, not your computer’s localhost URL.
  2. Create a host code on Linux, then connect with it from Android.
  3. Approve the correct device on Linux and choose the extra display in the browser sharing picker.
  4. Move windows onto that display using your computer. The website’s video is view-only; phone touch is not native Linux input.
If the extra display is not offered by the browser, this website cannot capture it in that configuration. Keep sharing codes private.
